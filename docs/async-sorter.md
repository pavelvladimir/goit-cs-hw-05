# Сортування файлів

Скрипт приймає вхідну й вихідну папки. `--workers` задає кількість одночасних копій
(за замовчуванням 8):

```bash
uv run --locked python async_sorter.py examples/source artifacts/sorted \
  --workers 4 --log-file artifacts/sorter.log --report artifacts/sorter.json
```

## Як це працює

`main` розбирає аргументи через `ArgumentParser`, створює `anyio.Path`
і запускає `sort_files` через `asyncio.run`.

1. `read_folder` асинхронно обходить папку, рекурсивно заходить у підпапки
   й додає знайдені файли в чергу.
2. Workers беруть шляхи з черги та викликають `copy_file`.
3. `copy_file` читає й записує блоки по 1 MiB. Готова копія отримує кінцеве ім'я.

Черга вміщує до `2 × workers` шляхів. Якщо вона заповнена, обхід чекає:
окрема задача для кожного файла наперед не створюється.
[AnyIO](https://anyio.readthedocs.io/en/stable/fileio.html) виконує файлові
операції в робочих потоках і надає async-інтерфейс. Швидкість залежить від диска
та розмірів файлів; більше workers не завжди означає швидше копіювання.

## Імена та папки

| Файл | Результат |
| --- | --- |
| `photo.JPG` | `jpg/photo.JPG` |
| `archive.tar.gz` | `gz/archive.tar.gz` |
| `README`, `.settings`, `name.` | Папка `no_extension` |
| Ще один `report.txt` | `txt/report_1.txt`, потім `_2` тощо |

Наявні файли не перезаписуються. За одночасного копіювання порядок суфіксів
може відрізнятися. Копіюється лише вміст, без прав і часових міток оригіналу.

Спочатку дані записуються у власний `.hw05-*.part`. Після закриття файла
`hardlink_to` створює кінцеве ім'я, а тимчасове видаляється. Якщо ім'я зайняте,
скрипт пробує наступний суфікс. Це працює і для двох незалежних процесів.
Цільова файлова система має підтримувати hard links.

## Помилки та переривання

Помилки обходу й копіювання записуються в stderr; `--log-file` додатково
дописує їх у UTF-8 файл. Інші доступні файли продовжують оброблятися.
Журнал і JSON-звіт мають бути поза вхідною та вихідною папками й не збігатися.
Журнал із кількома hard links відхиляється, щоб не змінити інший файл.

При Ctrl+C скрипт чекає поточної операції I/O, закриває файл і прибирає неповну
копію. Завершені копії залишаються та враховуються у статистиці. Помилка I/O
під час зупинки логується, але не скасовує сам запит на переривання.
Якщо прибрати тимчасовий файл не вдалося, це теж потрапляє в журнал.

Коди завершення: `0` — успіх, `1` — помилка або часткове копіювання,
`2` — помилка розбору аргументів, `130` — переривання. Пропущене посилання дає
попередження, але саме по собі не робить запуск невдалим.

## Обмеження

Вхідна папка має існувати; вихідна створюється за потреби. Вони не можуть
збігатися або містити одна одну. Перевірка враховує символічні
посилання, нормалізацію Unicode та ігнорує регістр навіть на Linux.
Посилання й спеціальні файли у джерелі пропускаються; цільова підпапка-посилання
відхиляється. Під час роботи не слід змінювати джерела або підміняти каталоги.
Глибина дерева обмежена рекурсією Python.

`fsync` не виконується, тому атомарна поява готового файла не гарантує збереження
після втрати живлення. `SIGKILL` може залишити `.part`; чужі тимчасові файли
скрипт не видаляє. Формат статистики описано в [JSON-звітах](reports.md).
