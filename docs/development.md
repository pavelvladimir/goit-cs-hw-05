# Розробка й тести

Проєкт використовує Python 3.14: у цій версії є `buffersize` для `Executor.map`.
Основні залежності — AnyIO, Matplotlib і jsonschema. Точні версії записані в `uv.lock`.

```bash
make init
make check
```

`make init` створює `.venv` через `uv sync --locked`. Оновлення пакетів виконується
окремо через `uv lock --upgrade`; після нього потрібно повторити перевірки й аудит.

## Що перевіряють тести

Тести працюють із тимчасовими файлами та HTTP-сервером на `127.0.0.1`.
Порт обирає ОС; після встановлення пакетів зовнішня мережа не потрібна.
Перевіряються вміст копій, частоти, CLI, графіки, JSON і поведінка після помилок.

У `test_processes.py` є чотири сценарії зі справжніми процесами: SIGINT під час
запису, I/O-помилка після сигналу, сигнал під час публікації та одночасне
копіювання двома CLI. `process_probe.py` лише узгоджує момент перевірки через
stdin/stdout; запис файлів і сигнали залишаються справжніми. На не-POSIX системах
ці тести пропускаються.

`test_permissions.py` перевіряє 13 відмов доступу без підміни файлових операцій.
Під root і на не-POSIX системах вони пропускаються. У [Rocky](rocky-linux.md)
весь набір має пройти без пропусків. Інші відмови, зокрема timeout і помилки
прибирання, відтворюються підміною відповідної операції.

Тести схеми охоплюють успіх, помилку й скасування, а також пошкоджені звіти.
Тести benchmark перевіряють розрахунки, результати й прибирання після помилки
або Ctrl+C зі збереженням попередніх запусків. Повне вимірювання швидкодії
запускається окремо. [Збережені результати](verification.md).

## Редактор і локальні файли

У `.vscode/` налаштовано `.venv/bin/python`, Ruff, pytest, mypy й Make tasks.
Рекомендовані розширення потрібно встановити окремо.
`.editorconfig` задає UTF-8, LF і чотири пробіли для Python.

Make зберігає кеші в `.cache/uv` та `.cache/matplotlib`. За потреби ті самі
шляхи можна задати для прямого запуску:

```bash
export UV_CACHE_DIR="$PWD/.cache/uv"
export MPLCONFIGDIR="$PWD/.cache/matplotlib"
```

`.venv/`, `.cache/`, `artifacts/`, `htmlcov/` і `coverage.xml` ігноруються Git.
Приклади в `examples/` та збережені результати в `docs/` належать до проєкту.
