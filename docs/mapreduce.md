# Частота слів через MapReduce

```bash
uv run --locked python mapreduce_words.py \
  https://www.gutenberg.org/files/1342/1342-0.txt \
  --top 10 --output artifacts/top_words.png
```

## Завантаження та слова

`download_text` завантажує звичайний текст через `urllib.request`.
Підтримуються HTTP(S) і перенаправлення. Кодування береться з `Content-Type`,
а без нього використовується UTF-8 із підтримкою BOM. Якщо є `Content-Length`,
скрипт перевіряє, чи відповідь отримана повністю.

Текст читається в пам'ять. Типовий ліміт — 20 MiB, timeout однієї мережевої
операції — 20 секунд; це не ліміт часу всього завантаження. HTML-теги не
видаляються, а заголовки й ліцензійний текст Gutenberg теж потрапляють у підрахунок.

Перед підрахунком текст проходить NFC-нормалізацію та `casefold()`.
Unicode-літери й приєднані діакритичні знаки зберігаються. Апострофи `’`, `ʼ`, `'`
приводяться до одного вигляду й допускаються всередині слова.
Дефіси, числа та пунктуація розділяють слова: `abc²def` дає `abc` і `def`.
Стоп-слова залишаються; лематизації немає.

## MapReduce

1. `map_function` створює пари `(word, 1)`.
2. `map_chunk` підсумовує повтори всередині порції — це локальний Combine.
3. `shuffle_function` групує часткові лічильники за словом.
4. `reduce_function` підсумовує їх.

Приклад для `cat dog cat` з порціями по два слова:

```text
Порції:   (cat, dog)          (cat)
Map:      (cat, 1), (dog, 1)  (cat, 1)
Combine:  {cat: 1, dog: 1}    {cat: 1}
Shuffle:  {cat: [1, 1], dog: [1]}
Reduce:   {cat: 2, dog: 1}
```

Map/Combine і Reduce виконуються через `ThreadPoolExecutor`, Shuffle — у головному
потоці. `buffersize=2 × workers` обмежує кількість завчасно відправлених порцій;
для цього потрібен Python 3.14. Текст і згруповані лічильники залишаються в пам'яті.

Потоки виконують вимогу завдання, але через GIL у звичайному CPython не гарантують
переваги над `Counter`. Порівняння є в [benchmark](benchmark.md).

## Параметри

| Аргумент | Типове значення | Для чого |
| --- | --- | --- |
| `url` | Gutenberg, книга 1342 | Адреса тексту |
| `--top` | `10` | Кількість слів на графіку |
| `--workers` | `4` | Кількість потоків |
| `--chunk-size` | `2000` | Слів у порції Map |
| `--timeout` | `20` | Timeout мережевої операції в секундах |
| `--max-bytes` | `20971520` | Ліміт відповіді в байтах |
| `--output` | `artifacts/top_words.png` | Шлях до графіка |
| `--show` | вимкнено | Відкрити вікно графіка |
| `--log-file` | лише stderr | Додатковий файл журналу |
| `--report` | вимкнено | Зберегти JSON-звіт |

## Графік і помилки

`visualize_top_words` будує горизонтальну діаграму `barh`: частота по осі X,
слова по осі Y, найбільша частота вгорі. Однакові частоти сортуються за
Unicode-порядком слів. Якщо слів менше за `--top`, показуються всі; порожній
текст завершується помилкою.

PNG можна зберегти без GUI, а `--show` потребує графічного середовища.
Формат визначає розширення `--output`: можна також зберегти SVG або PDF.
Без розширення використовується PNG.
Новий графік записується в тимчасовий файл і лише після цього замінює попередній
через `os.replace`. Якщо запис не вдався, старий графік залишається.

Шляхи графіка, журналу та звіту не повинні збігатися або містити один одного;
перевірка ігнорує регістр і нормалізує Unicode. Журнал із кількома hard links
відхиляється. Помилки HTTP, декодування й запису логуються.
Коди завершення: `0` — успіх, `1` — помилка, `2` — помилка розбору аргументів,
`130` — переривання. Частоти й SHA-256 тексту можна зберегти у [звіті](reports.md).
