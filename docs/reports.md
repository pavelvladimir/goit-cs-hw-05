# JSON-звіти

Обидва скрипти можуть зберігати результат через `--report`:

```bash
uv run --locked python async_sorter.py examples/source artifacts/sorted \
  --report artifacts/sorter.json
uv run --locked python mapreduce_words.py --report artifacts/words.json
```

Звіт створюється після успіху, помилки виконання або обробленого Ctrl+C.
Помилки argparse та конфлікти шляхів звіту, журналу й результатів відхиляються
без нового звіту. Відсутнє джерело або перетин вхідної й вихідної папок можуть
дати звіт `failed`, якщо шлях самого звіту допустимий.

## Спільні поля

| Поле | Значення |
| --- | --- |
| `schema_version` | Версія формату, зараз `1` |
| `task` | `async_sorter` або `mapreduce_words` |
| `started_at`, `finished_at` | Час UTC у форматі ISO 8601 |
| `elapsed_seconds` | Тривалість виконання |
| `status`, `exit_code` | Результат і код основної операції до запису звіту |
| `parameters` | Параметри запуску |
| `statistics` | Лічильники |
| `error` | Опис загальної помилки, якщо вона виникла |

Тривалість вимірюється через `perf_counter`: включає побудову графіка й очікування
`--show`, але не перевірку та запис самого звіту. Докладні помилки окремих файлів
залишаються в журналі.

## Сортування

`source` і `output` містять абсолютні шляхи. У `parameters` записані `workers`
і `chunk_bytes`, у `statistics`:

- `copied`, `bytes_copied` — кількість і розмір завершених копій;
- `skipped` — пропущені посилання та спеціальні файли;
- `errors` — помилки операцій, включно з невдалим прибиранням;
- `collisions` — зайняті імена, перевірені перед публікацією успішних копій.

Лічильники стосуються лише поточного запуску. Неповний `.part` не рахується
як копія. Уже опублікований файл враховується навіть при сигналі під час
публікації. Помилка I/O при зупинці збільшує `errors`, але статус лишається `cancelled`.

## Аналіз тексту

`source` завжди містить `requested_url`. Після успішного завантаження додаються
`final_url`, `charset`, `bytes_downloaded`, `sha256_bytes` і `sha256_text_utf8`.
Перший SHA-256 рахується для отриманих байтів, другий — для декодованого тексту
в UTF-8 до нормалізації. Сам текст у звіті не зберігається.

`parameters` містить `workers`, `chunk_size`, `top`, `timeout`, `max_bytes`.
У `statistics` записані `total_words`, `unique_words`, `errors`.
`frequencies` містить усі частоти, а `top_words` — пари `{word, count}` у порядку
графіка. `output` — запитаний шлях графіка. Якщо графік не вдалося записати,
частоти можуть бути правильними, але статус буде `failed`.

## Перевірка формату

Перед записом звіт перевіряється за
[JSON Schema v1](../schemas/run-report-v1.schema.json), Draft 2020-12.
Вона задає обов'язкові поля, типи, параметри, лічильники, SHA-256 і UTC-дати.
Зайві поля та невідомі версії відхиляються. Метадані завантаження мають бути
або повними, або відсутніми; `requested_url` залишається в обох випадках.

| Статус | Код | `errors` |
| --- | --- | --- |
| `success` | `0` | `0` |
| `failed` | `1` | Не менше `1` для sorter; `1` для MapReduce |
| `cancelled` | `130` | Невід'ємний для sorter; `0` для MapReduce |

Невдалий MapReduce містить `error`. При частковому копіюванні це поле може бути
відсутнім, бо окремі помилки вже є в журналі. Успішний і скасований запуск
загального `error` не мають.

`report_validation.py` перевіряє календарні дати через `FormatChecker`,
дозволяє UTC (`Z` або `+00:00`) і до шести знаків дробової секунди.
`NaN`, нескінченність і значення, несумісні з JSON, відхиляються.
Перевірка працює без мережі. У сторонньому валідаторі також потрібно ввімкнути
`format: date-time`. Сама схема не звіряє SHA-256 із текстом і не перераховує
частоти — це перевіряють тести. Зміна значення чи типу полів потребує нової версії схеми.

## Перевірка збережених звітів

```bash
make demo
make validate-reports
uv run --locked python -m scripts.validate_report \
  artifacts/demo/sorter.json artifacts/demo/words.json
```

Валідатор перевіряє всі передані файли й виводить `OK` або опис помилки.
Коди: `0` — усі файли валідні, `1` — помилка читання чи формату,
`2` — неправильний виклик. JSON від benchmark і Rocky має інший формат.

## Якщо звіт не вдалося записати

JSON спочатку записується в тимчасовий файл, а потім замінює попередній.
При помилці перевірки чи запису старий звіт залишається, команда повертає `1`
або зберігає `130` після Ctrl+C. Тому варто перевіряти код завершення та час у звіті.

Звіт і графік зберігаються окремо: відмова звіту не відкочує готовий графік
або скопійовані файли. При `SIGKILL` чи втраті живлення новий звіт не гарантований;
`fsync` не виконується. Шляхи й URL у demo-звітах стосуються тимчасових даних,
які після demo вже прибрані.
