# Перевірка в Rocky Linux

Потрібні Make, Bash і запущений Docker. Python та uv на хості не потрібні.
Запускайте від звичайного користувача, без `sudo`:

```bash
make check-rocky
```

Команда збирає локальний образ і запускає `make check`, demo та перевірку JSON.
Додатково звіряються лічильники demo, частоти, SHA-256 тексту й цілісність PNG.
Пропущені тести вважаються невдалим прогоном. Benchmark і аудит залежностей
запускаються окремо.

## Середовище

У [Dockerfile](../docker/tests.Dockerfile) Rocky Linux 10 і uv 0.13.0
зафіксовані digest, Python — версією 3.14.6. Python-пакети встановлюються
з `uv.lock`, а Make — з репозиторію Rocky. Звіт зберігає версії та ID готового
образу; повністю однаковий образ при складанні в інший день не гарантується.

Складання потребує мережі. До образу потрапляють код, конфігурація, приклади
й Markdown; `.git`, `.venv`, кеші та попередні результати виключені через
[dockerignore](../docker/tests.Dockerfile.dockerignore).

Під час перевірок контейнер:

- працює без зовнішньої мережі (`--network none`); локальний HTTP доступний;
- не встановлює пакети й не завантажує Python;
- використовує UID/GID користувача хоста, без root і додаткових capabilities;
- має кореневу файлову систему лише для читання та Linux tmpfs `/tmp` до 512 MiB;
- монтує тільки нову папку результатів, а після завершення видаляється.

Тести виконуються в Linux tmpfs, тому перевіряють права доступу й hard links
у Linux, а не на файловій системі macOS. Runner перевіряє Rocky, ненульовий UID
та відсутність активних інтерфейсів, крім loopback. Вимкнені тунельні інтерфейси
допускаються. На SELinux-хостах `:Z` застосовується лише до папки результатів.

## Тести прав доступу

У [test_permissions.py](../tests/test_permissions.py) є 13 сценаріїв
зі справжніми обмеженнями прав. CLI запускаються в окремих процесах;
права тимчасових файлів після тесту відновлюються.

| Обмеження | Що перевіряється |
| --- | --- |
| Джерело `000`: файл або підпапка | Помилка логується, доступні файли копіюються |
| Ціль або її підпапка `0555` | Попередні файли збережені, неповних копій немає |
| Каталог JSON `0555` | Код 1, помилка в stderr, старий звіт незмінний |
| Каталог PNG `0555` | Старий графік збережений, звіт містить помилку |
| Log `0444` або його каталог `0555` | Відмова до обробки, джерела незмінні |
| Каталог замість JSON | Помилка заміни, тимчасовий файл прибраний |

Для JSON і PNG обмежується каталог: файл `0444` у доступному для запису каталозі
все одно можна замінити атомарно. Під root і на не-POSIX системах ці тести
пропускаються, тому Rocky-runner вимагає звичайного користувача й нуль пропусків.

## Результати

Кожний запуск створює `artifacts/rocky/<UTC-час>-<суфікс>/` і друкує цей шлях.
Попередні запуски не перезаписуються. У папці залишаються:

| Файли | Зміст |
| --- | --- |
| `build.log`, `check.log`, `exit-code.txt` | Логи й код завершення |
| `image.json`, `docker-version.json` | Образ і версії Docker |
| `results.json` | Підсумок, середовище, команди, час і SHA-256 входів |
| `pytest.xml` | Кількість тестів, помилки й пропуски |
| `.coverage`, `coverage.json`, `coverage.xml`, `htmlcov/` | Покриття |
| `demo/` | Два JSON-звіти й PNG |

При ранній помилці частина файлів може бути відсутня. `results.json` має власний
формат; схема CLI застосовується лише до двох demo-звітів. SHA-256 охоплюють код,
тести, схему, приклади й конфігурацію, але не Markdown і збережені результати.

Останній прогін: Rocky Linux 10.2 ARM64 у Docker Desktop, 170 тестів без пропусків.
Це перевірка контейнера з ядром LinuxKit; AMD64, окремий сервер Rocky,
інші файлові системи та SELinux enforcing не перевірялися.
[Докладні результати](verification.md#rocky-linux), [JSON запуску](rocky-results.json).
